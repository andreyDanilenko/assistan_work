# Сборка и передача текущего прототипа

Краткие команды сборки и решение `permission denied` — в [BUILD.md](../BUILD.md).

Готовый CLI умеет читать Loki, анализировать файл и выполнять `watch`: периодически проверять свежие логи и отправлять сводки в Telegram. SQLite внутри приложения сохраняет исходные события до 48 часов, а отдельный JSON — состояние уведомлений и очередь. PostgreSQL, начальная догрузка прошлых 48 часов, REST и ответы бота на запрос заказа пока не входят в поставку.

Коллеге **не нужны Go, установленная SQLite или отдельный сервер базы**. Для сборки разработчику нужен Go не ниже версии, указанной в `go.mod`. Для SQLite используется драйвер `modernc.org/sqlite` на Go; его версия и зависимости закреплены в `go.mod`/`go.sum`. `CGO_ENABLED=0` сохраняется для всех четырех платформ. Бинарник стал больше из-за встроенного движка базы.

## Собрать нужную платформу

Команды ниже выполняются в терминале macOS/Linux из корня репозитория, где лежит `go.mod`. Пример для текущего macOS/Linux:

Первое скачивание зависимостей требует доступа к Go-модулям; SQLite вручную не устанавливается.

```sh
go mod download
mkdir -p dist
CGO_ENABLED=0 go build -trimpath -o dist/lokictl ./cmd/lokictl
```

Для другого компьютера выберите цель:

| Платформа | GOOS | GOARCH | Бинарник |
| --- | --- | --- | --- |
| Mac Apple Silicon | `darwin` | `arm64` | `lokictl` |
| Mac Intel | `darwin` | `amd64` | `lokictl` |
| Linux Intel/AMD 64 бит | `linux` | `amd64` | `lokictl` |
| Windows Intel/AMD 64 бит | `windows` | `amd64` | `lokictl.exe` |

Пример подготовки четырех платформ; это пути результата сборки, не имена опубликованных архивов:

```sh
mkdir -p dist/darwin-arm64 dist/darwin-amd64 dist/linux-amd64 dist/windows-amd64
GOOS=darwin GOARCH=arm64 CGO_ENABLED=0 go build -trimpath -o dist/darwin-arm64/lokictl ./cmd/lokictl
GOOS=darwin GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -o dist/darwin-amd64/lokictl ./cmd/lokictl
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -o dist/linux-amd64/lokictl ./cmd/lokictl
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -o dist/windows-amd64/lokictl.exe ./cmd/lokictl
```

Не запускайте чужую платформу на машине сборки для проверки. Успешная кросс-сборка подтверждает компиляцию; запуск нужно проверить на целевой ОС.

## Что передавать

Для каждой платформы создайте отдельную папку только с этими файлами:

```text
loki/
  lokictl                  # На Windows: lokictl.exe
  .env.example             # Пустые токены и chat_id
  QUICKSTART.md            # Инструкция для сотрудника
  THIRD_PARTY_NOTICES.txt   # Лицензии включенных зависимостей
  examples/
    orders-analysis.txt    # Только синтетические события
```

Упакуйте эту папку, не весь репозиторий. В поставку не включайте рабочий `.env`, `local/`, SQLite-базу и ее служебные файлы, очередь, отчеты, реальные логи, токены или `examples/loki-query-response.txt`. База не зашифрована и содержит исходные чувствительные данные. Проверьте, что скрытый `.env.example` действительно попал в архив. Сохраните исполняемый бит Unix-бинарника либо укажите команду `chmod u+x` из инструкции.

Рядом с готовыми архивами подготовьте `SHA256SUMS` с SHA-256 каждого архива. Подпишите платформу в имени и передавайте контрольные суммы вместе с набором. Конкретные имена архивов фиксируются при подготовке релиза; эта инструкция не утверждает, что архивы уже собраны.

## Проверить удобство запуска

1. Распаковать чистый набор и открыть терминал в папке с бинарником.
2. Запустить `./lokictl --help` и `./lokictl analyze --file examples/orders-analysis.txt` без токенов. На Windows — `.\lokictl.exe` и PowerShell.
3. Создать личный `.env` из шаблона; на macOS/Linux ограничить права через `chmod 600 .env`. На Windows сохранить файл в UTF-8 под точным именем `.env` в личной папке.
4. Заполнить отдельно выданный токен Grafana, при необходимости подключить VPN и доверенный корпоративный сертификат. Программа читает настройки из текущей папки, не автоматически рядом с бинарником.
5. Проверить `check`, затем `watch --once --dry-run`. Предпросмотр читает Loki, но не требует Telegram, не открывает базу и не меняет состояние.
6. Запустить `db-status` без рабочих токенов: команда создает базу при отсутствии, применяет срок 48 часов и показывает статистику. `db-cleanup --timeout 2m` также выполняет очистку; это не команды только для чтения.
7. Настроить разрешенную группу по [QUICKSTART](../QUICKSTART.md). Запуск `watch` включает реальную отправку; убедиться в создании `local/loki.db`, остановить через `Ctrl+C` и проверить продолжение с прежней базой и состоянием. Обновлять бинарник следует после остановки старого процесса; `.env` и `local/` не заменяются файлами из архива.

Для независимых копий используйте отдельные настройки и файлы состояния. Два монитора на разных компьютерах с одним ботом и получателем могут присылать дубли: локальная блокировка действует только на один файл. Согласуйте один рабочий монитор для общего чата. `telegram-chats` читает `getUpdates` и не должен конкурировать с другим обработчиком того же бота; активный webhook автоматически не отключается.

Путь локальной базы задается `WATCH_DB_FILE`, по умолчанию `local/loki.db`, относительно текущей рабочей папки. `DATABASE_URL` не нужен и не поддерживается. На Unix база создается с правами `0600`; на Windows используйте личную папку без общего доступа. Постоянная работа на ноутбуке требует доступной сети и отключенного сна на время наблюдения; фонового системного сервиса пока нет.

## Готовые комплекты

На Mac/Linux с Go, `zip` и `shasum` весь комплект собирается одной командой:

```sh
sh scripts/build-release.sh
```

Этот способ не требует права на исполнение скрипта. Для прямого запуска сначала выполните `chmod u+x scripts/build-release.sh`. Скрипт создает комплекты в `dist/`; локальный `bin/lokictl` обновляется отдельно по [BUILD.md](../BUILD.md).

Архивы: `dist/lokictl-darwin-arm64.zip`, `dist/lokictl-darwin-amd64.zip`, `dist/lokictl-linux-amd64.zip`, `dist/lokictl-windows-amd64.zip`. Контрольные суммы — `dist/SHA256SUMS`. Каждый архив содержит только бинарник, `.env.example`, QUICKSTART, `THIRD_PARTY_NOTICES.txt` и синтетический пример. Лицензии нужны для распространения встроенного SQLite-драйвера и его зависимостей. Кросс-сборка не заменяет проверку запуска на компьютере коллеги.

После добавления SQLite в этой итерации пересобирается только комплект `darwin-amd64` для текущего Mac. Остальные архивы могут относиться к предыдущей версии; перед передачей для другой ОС выполните `sh scripts/build-release.sh`.
