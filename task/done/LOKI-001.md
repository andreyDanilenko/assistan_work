# LOKI-001 Разделить приложение на независимые компоненты и передавать зависимости явно

> Карточка фиксирует результат раннего этапа. Возможности первой версии Telegram описаны в [текущей приемке](../prototype.md).

- **Тип:** Задача
- **Статус:** Выполнено
- **Приоритет:** Средний
- **Компонент:** Архитектура
- **Этап:** Выполнено
- **Зависимости:** Нет

## Цель

Разделить получение, обработку и представление логов, чтобы каждый компонент можно было читать, проверять и заменять отдельно.

## Что сделано

- [x] Выделены пакеты `config`, `loki`, `input`, `analyzer`, `model`, `app`, `cli`, `telegram` и `utils`.
- [x] Компоненты создаются и соединяются явно в `cmd/lokictl/main.go`, без контейнера DI.
- [x] Сервисы принимают источники и анализатор через небольшие интерфейсы; HTTP-клиенты передаются конструкторам.
- [x] Сетевые настройки загружаются один раз. Сервис заказов получает настройки проекта без токенов.
- [x] Локальный анализ отделен от сетевых команд и загрузки `.env`.

## Критерии приемки

- [x] Анализатор работает с готовыми записями и не обращается к Loki или Telegram.
- [x] Сервис и CLI проверяются с подставными зависимостями без рабочих внешних сервисов.
- [x] Точка входа показывает порядок создания и передачи компонентов.

## Границы задачи

Интерфейсы и компоненты хранения, регулярного сбора и REST еще не реализованы. Архитектура допускает их добавление, но сама по себе не обеспечивает суточную историю.
