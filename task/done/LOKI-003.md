# LOKI-003 Обеспечить безопасное выполнение HTTP запросов

> Карточка фиксирует результат раннего этапа. Возможности первой версии Telegram описаны в [текущей приемке](../prototype.md).

- **Тип:** Задача
- **Статус:** Выполнено
- **Приоритет:** Средний
- **Компонент:** HTTP
- **Этап:** Выполнено
- **Зависимости:** [LOKI-002](LOKI-002.md)

## Цель

Ограничить время и объем сетевых операций и исключить раскрытие токенов при ошибках или перенаправлениях.

## Что сделано

- [x] Общий HTTP-клиент задает таймаут, запрещает редиректы и сохраняет стандартную проверку TLS.
- [x] Клиент Loki проверяет HTTPS и параметры подключения до запроса; HTTP допустим только при явном разрешении в его настройках.
- [x] Запросы принимают `context.Context` и поддерживают отмену.
- [x] Loki ограничивает размер ответа, общий объем и количество запросов; Telegram ограничивает ответ `getMe`.
- [x] Ошибки не включают исходные тела ответов, токены и адрес Telegram с токеном в пути.

## Критерии приемки

- [x] Перенаправление не приводит к повторной отправке авторизованного запроса на другой адрес.
- [x] Превышение лимита, отмена и таймаут завершают операцию с понятной ошибкой.
- [x] Тестовые чувствительные значения не попадают в диагностические сообщения.

## Границы задачи

Это защита существующих клиентских запросов. Серверная авторизация REST, управление правами пользователей и повторная доставка уведомлений сюда не входят.
