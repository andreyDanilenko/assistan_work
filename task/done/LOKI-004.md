# LOKI-004 Реализовать чтение меток проектов и одной страницы логов Loki

> Карточка фиксирует результат раннего этапа. Возможности первой версии Telegram описаны в [текущей приемке](../prototype.md).

- **Тип:** Задача
- **Статус:** Выполнено
- **Приоритет:** Средний
- **Компонент:** Loki
- **Этап:** Выполнено
- **Зависимости:** [LOKI-003](LOKI-003.md), [LOKI-007](LOKI-007.md)

## Цель

Проверять доступ к Loki и получать исходные данные независимо от анализатора.

## Что сделано

- [x] Реализованы `GetLabels`, `GetLabelValues`, `GetProjects` и `QueryRange`.
- [x] Запросы проходят через прокси источника Grafana с Bearer-токеном и выбранной организацией.
- [x] Период передается в наносекундах; направление запросов логов — от старых событий к новым.
- [x] Ответ содержит исходный JSON и проверенную модель потоков либо список значений метки.
- [x] Заполненная страница помечается как потенциально ограниченная; проверяются структура и временные границы ответа.

## Критерии приемки

- [x] Сохраняются базовый путь Grafana, UID источника и заголовки доступа.
- [x] Ошибочные параметры отклоняются до сетевого запроса.
- [x] Пустой успешный ответ отличается от ошибки и возможного достижения лимита.
- [x] Пользователь подтвердил рабочий доступ командой `check` и получение реальных логов.

## Границы задачи

`QueryRange` выполняет один запрос. Полная история проекта и каталоги за все время этим методом не гарантируются; анализ не запускается автоматически.
