# LOKI-005 Реализовать ограниченную выгрузку периода с разбиением запросов

> Карточка фиксирует результат раннего этапа. Возможности первой версии Telegram описаны в [текущей приемке](../prototype.md).

- **Тип:** Задача
- **Статус:** Выполнено
- **Приоритет:** Средний
- **Компонент:** Loki
- **Этап:** Выполнено
- **Зависимости:** [LOKI-004](LOKI-004.md)

## Цель

Получать ограниченный период, не считая заполненную страницу доказательством полной выгрузки.

## Что сделано

- [x] Добавлен клиентский метод `FetchLogs` с результатом `Complete`, `Reason`, числом запросов и прочитанных байт.
- [x] Заполненная страница заменяется двумя непересекающимися интервалами `[start,end)`; ее предварительные записи не учитываются повторно.
- [x] Сохраняются точные timestamps, метки, metadata и кратность одинаковых событий.
- [x] Учитываются бюджеты записей, запросов и байт, включая отброшенные предварительные ответы.
- [x] Насыщенный интервал в одну наносекунду явно признается неполным.

## Критерии приемки

- [x] Разбиение не теряет записи на границах и не увеличивает счетчики за счет предварительной страницы.
- [x] Одинаковые timestamps не обходятся простым сдвигом на следующую наносекунду.
- [x] Достижение лимита возвращает неполный результат с причиной; HTTP-ошибка не становится успешной пустой выборкой.

## Границы задачи

Метод реализован только в клиенте: CLI `logs` продолжает вызывать одну страницу. Сохранения в БД, контрольной позиции и фонового цикла нет. `Complete` относится к данным, доступным при чтении; запоздавшие события могут появиться позже.
