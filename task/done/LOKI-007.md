# LOKI-007 Описать модели Loki и сообщения заказа и сохранить примеры

> Карточка фиксирует результат раннего этапа. Возможности первой версии Telegram описаны в [текущей приемке](../prototype.md).

- **Тип:** Задача
- **Статус:** Выполнено
- **Приоритет:** Средний
- **Компонент:** Модели
- **Этап:** Выполнено
- **Зависимости:** [LOKI-001](LOKI-001.md)

## Цель

Описать внешний ответ Loki и внутреннее сообщение `sds-orders` отдельно, сохранив понятные примеры для чтения и проверки без сети.

## Что сделано

- [x] Созданы `LokiQueryResponse`, `LokiQueryData`, `LokiStream`, `LokiEntry` и общий `LogRecord`.
- [x] Массив записи Loki разбирается с точным `int64` временем в наносекундах и необязательными metadata.
- [x] `OrderLog` описывает известные поля сообщения: время приложения, контекст, ID, позицию, владельца, реселлера, статус и текст.
- [x] Отсутствующие числовые поля отличаются от нуля; `endTime` сохраняется как JSON без предположения о типе.
- [x] Добавлены TXT-пример ответа Loki и отдельный демонстрационный набор событий заказа.

## Критерии приемки

- [x] JSON ответа проходит обратное преобразование без изменения данных примера.
- [x] Наносекунды Loki не смешиваются с миллисекундами приложения.
- [x] ID позиции и родительского заказа остаются раздельными.
- [x] Разбор сообщения не назначает бизнес-исход заказа.
