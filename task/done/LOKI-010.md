# LOKI-010 Связать заказы с реселлерами и показать конфликты принадлежности

> Карточка фиксирует результат раннего этапа. Возможности первой версии Telegram описаны в [текущей приемке](../prototype.md).

- **Тип:** Задача
- **Статус:** Выполнено
- **Приоритет:** Средний
- **Компонент:** Анализатор
- **Этап:** Выполнено
- **Зависимости:** [LOKI-009](LOKI-009.md)

## Цель

Получать сводку заказов по реселлерам без ложной привязки при отсутствующих или противоречивых данных.

## Что сделано

- [x] Для заказа собираются наблюдаемые `ResellerID` из его событий.
- [x] Если известен один непустой ID, он используется в сводке заказа; исходные события без ID не дополняются выдуманным значением.
- [x] Разные непустые ID устанавливают `ResellerConflict`, а общая принадлежность остается неопределенной.
- [x] Сводки разделяются по проекту и реселлеру; неизвестная и конфликтующая принадлежность попадают в отдельную группу с пустым ID.
- [x] Количество заказов, состояния и число сообщений об ошибках считаются отдельно.

## Критерии приемки

- [x] Позднее событие без реселлера не стирает ранее установленную однозначную связь.
- [x] При конфликте порядок входных событий не выбирает случайного реселлера.
- [x] Повторные ошибки одного заказа увеличивают число ошибок, но не число заказов.
- [x] Одинаковые ID в разных проектах не объединяются.

## Границы задачи

Используются только ID, присутствующие в загруженной выборке. Справочник реселлеров, названия компаний, права доступа и связь с данными админки пока отсутствуют.
