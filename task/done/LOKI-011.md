# LOKI-011 Добавить понятный консольный отчет по заказам и ошибкам

> Карточка фиксирует результат раннего этапа. Возможности первой версии Telegram описаны в [текущей приемке](../prototype.md).

- **Тип:** Задача
- **Статус:** Выполнено
- **Приоритет:** Средний
- **Компонент:** CLI
- **Этап:** Выполнено
- **Зависимости:** [LOKI-006](LOKI-006.md), [LOKI-009](LOKI-009.md), [LOKI-010](LOKI-010.md)

## Цель

Сделать результат анализа понятным без чтения внутренних названий состояний и исходного JSON.

## Что сделано

- [x] Команда `analyze --file` показывает общие счетчики, состояния и историю событий по-русски.
- [x] По умолчанию выводятся до 10 заказов: сначала с ошибками, затем без подтверждения этапа, затем остальные.
- [x] `--all-orders` снимает ограничение числа историй; общие сводки всегда учитывают весь файл.
- [x] В истории показаны последние пять событий; более старая последняя ошибка выводится отдельно.
- [x] Подписаны причины пропуска, реселлеры и конфликты; демонстрационные данные определяются по явной метке.
- [x] Идентификаторы экранируются для безопасного вывода в терминал.

## Критерии приемки

- [x] Демонстрационный пример показывает подтвержденный этап после ошибки и отдельный заказ с неизвестным исходом.
- [x] Ограничение подробностей не меняет итоговые счетчики и не скрывает проблемные заказы за успешными.
- [x] Смешанная выборка не объявляется целиком учебной; сырой текст сообщений не печатается.

## Границы задачи

ID берутся из файла, поэтому отчет не является обезличенным. Он описывает наблюдаемый фрагмент и не доказывает окончательный бизнес-исход заказа.
