# LOKI-013 Упростить структуру проекта и вынести тесты из рабочего кода

> Карточка фиксирует результат раннего этапа. Возможности первой версии Telegram описаны в [текущей приемке](../prototype.md).

- **Тип:** Задача
- **Статус:** Выполнено
- **Приоритет:** Средний
- **Компонент:** Архитектура
- **Этап:** Выполнено
- **Зависимости:** [LOKI-001](LOKI-001.md), [LOKI-006](LOKI-006.md), [LOKI-009](LOKI-009.md), [LOKI-012](LOKI-012.md)

## Цель

Сократить дробление проекта и отделить проверочный код, сохранив понятные границы компонентов.

## Что сделано

- [x] Рабочий код сокращен с 40 до 17 Go-файлов за счет объединения небольших файлов по ответственности.
- [x] Создание зависимостей перенесено непосредственно в `main.go`; отдельный слой `bootstrap` убран.
- [x] Тесты вынесены в `tests/<компонент>`, а проверки запуска — в `tests/integration`.
- [x] Проверки используют публичные API: закрытые функции не экспортировались ради тестов.
- [x] Общая настройка HTTP находится в `utils`; получение, анализ, модели и CLI остаются отдельными компонентами.

## Критерии приемки

- [x] Рядом с рабочими файлами `cmd/` и `internal/` нет файлов `*_test.go`.
- [x] Для поиска сценария не нужно переходить через отдельный контейнер или слой сборки зависимостей.
- [x] Проверки буквального чтения `.env`, TXT, моделей и анализатора сохранены после переноса.
