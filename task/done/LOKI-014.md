# LOKI-014 Проверить компоненты и запуск CLI без рабочих внешних сервисов

> Карточка фиксирует результат раннего этапа. Возможности первой версии Telegram описаны в [текущей приемке](../prototype.md).

- **Тип:** Задача
- **Статус:** Выполнено
- **Приоритет:** Средний
- **Компонент:** Проверки
- **Этап:** Выполнено
- **Зависимости:** [LOKI-005](LOKI-005.md), [LOKI-008](LOKI-008.md), [LOKI-011](LOKI-011.md), [LOKI-012](LOKI-012.md), [LOKI-013](LOKI-013.md)

## Цель

Проверить поведение компонентов и их соединение без рабочих токенов и обращений к внешним сервисам.

## Что сделано

- [x] Созданы отдельные наборы тестов конфигурации, HTTP, Loki, файлов, моделей, анализа, сервисов, CLI и Telegram.
- [x] Сервисы проверяются с подставными зависимостями, сетевые клиенты — с тестовым транспортом и локальными серверами `httptest`.
- [x] Интеграционные проверки запускают CLI и проверяют справку, отсутствие токена и автономный анализ.
- [x] Проверяются неверные данные, отмена, лимиты, повторные события, границы времени и отсутствие утечки тестовых секретов.
- [x] После предыдущих изменений кода успешно выполнены `go test -race ./...`, `go vet ./...` и сборка CLI.

## Критерии приемки

- [x] Наборы компонентов можно запускать отдельно через `go test ./tests/<компонент>`.
- [x] Проверки не требуют действующих учетных данных Grafana и Telegram.
- [x] Сборка исполняемого файла и основные сценарии завершились без выявленных ошибок.

## Границы задачи

Карточка фиксирует ранее выполненную проверку; при создании этой документации тесты заново не запускались. Успех тестов не подтверждает доступность рабочих сервисов и не проверяет еще отсутствующие БД, сборщик или уведомления.
