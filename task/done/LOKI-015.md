# LOKI-015 Описать запуск архитектуру правила обработки и шаги кода

> Карточка фиксирует результат раннего этапа. Возможности первой версии Telegram описаны в [текущей приемке](../prototype.md).

- **Тип:** Задача
- **Статус:** Выполнено
- **Приоритет:** Средний
- **Компонент:** Документация
- **Этап:** Выполнено
- **Зависимости:** [LOKI-013](LOKI-013.md), [LOKI-014](LOKI-014.md)

## Цель

Сделать проект читаемым для следующего разработчика: от первого запуска до изменения правил анализа.

## Что сделано

- [x] README описывает получение токенов, переменные окружения, сборку, команды, ошибки подключения и автономный анализ.
- [x] Документированы структура пакетов, ручной DI и рекомендуемый порядок чтения исходников.
- [x] Объяснены два уровня JSON, точность времени, различие одной страницы и `FetchLogs`, текущие ограничения анализа.
- [x] В `spec/` сохранены исходная цель, выполненные этапы, план обработки, будущего хранения и REST.
- [x] В рабочий Go-код добавлены короткие русские комментарии к значимым типам, шагам, ограничениям и неоднозначным правилам.
- [x] При добавлении комментариев отдельно проверено совпадение всех Go-токенов вне комментариев: поведение не менялось.

## Критерии приемки

- [x] По документации можно настроить проект и запустить раздельные проверки Loki, Telegram и файла.
- [x] Читателю явно видна разница между уже работающими командами и планируемым прототипом.
- [x] Комментарии поясняют причины решений: неоднозначный ID, конфликт реселлера, подтверждение этапа и защита токенов.
