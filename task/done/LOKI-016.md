# LOKI-016 Проверить анализ на реальной пятиминутной выгрузке

> Карточка фиксирует результат раннего этапа. Возможности первой версии Telegram описаны в [текущей приемке](../prototype.md).

- **Тип:** Задача
- **Статус:** Выполнено
- **Приоритет:** Средний
- **Компонент:** Анализатор
- **Этап:** Выполнено
- **Зависимости:** [LOKI-008](LOKI-008.md), [LOKI-009](LOKI-009.md), [LOKI-010](LOKI-010.md), [LOKI-011](LOKI-011.md)

## Цель

Сверить локальный анализ с предоставленным пользователем реальным экспортом и уточнить правила на наблюдаемых сообщениях.

## Что сделано

- [x] Разобраны все 1000 строк экспорта без пропусков; результат сопоставлен с независимым подсчетом.
- [x] Найдены 134 заказа: 124 с `order provisioned`, 7 с ошибками без подтверждения в этом фрагменте и 3 только с чтением.
- [x] Разделены 8 сообщений об ошибках и 7 затронутых заказов: 5 таймаутов и 3 сообщения «заказ не найден» на двух заказах.
- [x] Установлено, что пять таймаутов относятся к одному реселлеру; сохранена сводка с историями заказов.
- [x] Добавлены правила таймаута подключения и пропуска выдачи артефактов, а также их регрессионные проверки.

## Критерии приемки

- [x] Повторная ошибка одного заказа не увеличивает число уникальных заказов.
- [x] Отчет объясняет наблюдаемую проблему, не приписывая таймаут конкретной неизвестной системе.
- [x] Отсутствие подтверждения внутри выгрузки не объявляется окончательным падением заказа.

## Границы задачи

Файл покрывает примерно 5 минут 13 секунд: это лимит 1000 строк из выбранных в Grafana трех часов. Отчет расположен в игнорируемой папке `local/` и доступен в рабочем проекте; реальные ID в эту карточку не перенесены. Суточная полнота и дальнейшая судьба заказов не проверялись.
